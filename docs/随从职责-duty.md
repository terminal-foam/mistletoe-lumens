# 随从职责 duty（Classic 2.3.0）

> 版本 2.3.0。与 Classic 2.0.0 同一个 mod id，**不能并装**，替换 jar 即可。
> 这套功能在源码里直接实现（不再用 ASM 补丁）。数据分别存在实体 NBT 与世界 `SavedData`。

## 1. 玩家随从：驻守 / 跟随 / 绑床

前提：随从属于你（已驯服），并且离你 **32 格内**。

| 操作 | 做法 |
|---|---|
| **打开随从界面** | 手持任意物品 **右键随从**（和原来开背包一样），界面顶部有 **跟随 / 驻守** 两个按钮 |
| **跟随 / 驻守切换** | 点界面顶部的 **跟随** 或 **驻守** 按钮 |
| **设驻守点** | 拿 **指南针**，**潜行 + 右键随从**，再 **右键一个方块**（脚下要有站立空间；有床时以床为准） |
| **退出驻守** | 驻守状态下再拿 **指南针 + 潜行右键** 随从，恢复跟随 |
| **强制绑定床** | 拿 **纸**，**潜行 + 右键随从**，再 **右键一张完整的床**（头/脚都在、朝向一致；会锁定，自动认床不再覆盖） |
| **改半径** | `/lumen_duty guard <随从> <12\|24\|40>`，然后右键方块选点 |
| **恢复跟随** | `/lumen_duty follow <随从>` |
| **查看状态** | `/lumen_duty status <随从>`（驻守/床/中心/是否在睡） |

规则：

- **自动认床**：没有绑定床时，每 2 秒在 **16 格**内找一张没人用的完整床自动绑定；村民附近的床、其他随从已绑的床会跳过；纸绑定是**强制**的，锁定后不会再被自动覆盖；
- **驻守以床为中心**：有绑定床时，无论指南针选点还是界面「驻守」，防区中心都用那张床；
- **界面按钮**：打开随从背界面后，顶部「跟随」「驻守」直接切换；「驻守」有床 → 立即以床为中心驻守，没床 → 进入 20 秒选点；
- 默认驻守半径 **24 格水平、上下各 8 格**；选点有效 **20 秒**，随从不能离选点太远（8 格内点击、32 格内随从）；
- 物品**不消耗**；选点会校验维度、距离、能否站立；
- 驻守时：目标超出防区不追；**回岗和回床会独占寻路**（不会一边跟一边站岗）；
- 夜里会尝试回绑定的床睡觉；**床被占用/被拆** 时不会硬传送，绑定保留；
- 正在交战、被攻击、袭击中会中断睡眠；
- 原来「食物驯服、骑乘、蹲下右键坐下」都保留；**有村庄/领队职责的随从不能用食物驯服**。

## 2. 村庄守卫

### 自动生成：每座哨所一位（2.3.30 起）

不再按村庄的钟投放，而是**按「流明哨所」建筑投放：有几座哨所，就有几位无主守卫**，并且直接生成在**建筑内部**。

- 哨所是本模组加进原版村庄的独立建筑（7×19×17 石塔，内有床、箱子、营火和灵魂沙气泡柱电梯），目前**只接入平原（plains）**（2.7.3 按需求移除了草原/savanna）；沙漠 / 雪原 / 针叶林留待后续美术版本，工具已支持 `--biomes` 一键扩展；
- 每座哨所内部有一个不可见、无碰撞、不可破坏的锚点方块 `mistletoe:guard_post`，守卫的脚就站在这一格（主厅北门内侧）；
- 玩家 64 格内发现锚点才处理；`mistletoe_village_guards` 按**锚点坐标**记录（键前缀 `post@`），不会重复投放；
- 锚点上方被堵住时先不投放，清空后再补；
- 靠近已有村庄守卫的锚点不会重复生成，存档丢失 SavedData 时也不会刷出第二个；
- 守卫阵亡后仍按本节的复活规则在**床边 → 锚点附近**复活；
- 不需要 OP 指令。**没有哨所的村庄不会自动出守卫**，可用下面的命令手动登记。

> **兼容性代价**：为了把哨所塞进原版村庄，本模组**覆写**了
> `data/minecraft/worldgen/template_pool/village/plains/houses.json` 这 1 个文件
> （其余群系保持原版，不覆写）。
> 1.21.1 的 NeoForge 21.1.248 没有"追加模板池元素"类的 StructureModifier（实测只有
> AddSpawns / ClearSpawns / RemoveSpawns），数据包层面无法原地追加，只能整体替换。
> 所以本模组与其他同样往原版村庄加建筑的模组/数据包**互斥**，后加载者生效。
> 出现频率用 `tools/merge_village_pool.py --weight N` 重新生成（默认 10：平原房屋池 10.3%、草原 11.0%，即每个村庄约 1 座，常有 2 座）。

> **老存档提醒**：结构按区块在世界生成时放置，**已经生成过的村庄不会长出哨所**。
> 需要新世界，或探索未加载过的区块。

### 手动登记（需要 OP）

把**未驯服**的随从登记为村庄守卫：

```
/lumen_duty village <随从> <村中心> <战时岗位>
/lumen_duty village_bed <随从> <床>
```

- 中心/岗位用 `x y z` 坐标；岗位必须是**已加载、脚下有支撑、上方两格空气**的位置；
- 岗位必须在村中心 **24 格内**；
- 床必须是**完整**的床，且在中心 24 格内。

行为：

- 无主也能生活：白天在村中心附近活动，夜里回分配的床；
- 本村有**有效袭击**时：去岗位驻守，只攻击**本场袭击的成员**；
- 可以离岗几格迎敌，但**敌人跑出防区就放弃**，打完回岗位；
- 阵亡后：袭击结束后优先在**床边**、其次在**村中心附近**复活；
- 复活任务按维度存进存档（`mistletoe_village_respawns`），**关档/重启不会丢**；复活点不可用（区块未加载/被占）就保留任务，不硬塞。

## 2.4 流明灯（2.3.9）

- 获取：`/give @s mistletoe:lumen_lamp`，或创造模式「工具与实用物品」页；**也可以用红宝石向流明换（Day 7 解锁）**——合成配方已在 2.6.2 移除；
- 右键举灯（短抬手 + 风铃 + 冷光），**不消耗**，冷却 1.5 秒；
- **手持照明（2.6.4）**：灯拿在主手或副手时会照亮周围——**走动态光源模组那条路**：
  本模组自带 `assets/lambdynlights/dynamiclights/item/lumen_lamp.json`（亮度 15），
  装了 [LambDynamicLights] 之类的模组就会自动读到它。
  没有这类模组时不发光（曾做过"放隐形光源方块"的兜底，按需求已移除）。
- 在有效袭击附近举灯（**袭击中心水平 64 格内**）会立即求援，**不要求第 4 波**；
- 15 人全部有安全落点才进场，成功才回铃；没有有效袭击时只有声音和闪光；
- 每场袭击只能应答一次，多人同时举灯不会刷出第二队；
- 自动援军（2.3.6 起，袭击之兆 ≥2 + 第 4 波）仍然保留，灯只是提前手动召唤。

## 2.5 流明援军（2.3.6，自动触发）

袭击达到条件时，自动派遣 **1 位流明·星 + 14 名临时随从**（共 15 人）：

- 触发（2.6.3）：**袭击打到第 4 波**、场上仍有活着的袭击者、玩家在袭击中心 **64 格内**；每场袭击只派一次。不足 4 波的袭击退到最后一波（否则永远等不到）。**用流明灯则立即召唤，不等波数**；
- 每场袭击只派遣一次（`mistletoe_lamp_relief`），**15 人按批进场**：`ReliefDispatch` 先准备/校验再插入，中途失败会倒序回滚，绝不会留下半队；
- 岗位用 `ReliefTactics` 选择，并做**真实寻路可达性检查**：外围不跨扇区、路径不越界、被击退到界外只走逐步向内的归位路径；隔墙不可达的最近目标会被跳过（2.3.8，lamp.2）；
- 人员与分工：
  - **8 名外围**：各自守一个扇区（中心外 14/20 格），只打自己扇区附近的袭击者；
  - **2 名中枢**：绕钟的 4 个路点巡逻（±6 格），不站桩；
  - **2 名护民**：围绕村里村民最密的区域巡逻（±3/±2 格）；
  - **2 名护送 + 流明本人**：**全程追踪**袭击者（活动范围 96 格），流明在 5–10 格用斩击、近身平砍，优先打劫掠兽；
- 援军只打本场袭击的成员；玩家打不了他们、也无法驯服；死亡不掉落、不给经验；
- 援军流明**不显示 Boss 血条、不进入终局蓄力/自爆**；
- 袭击结束/失败后自动撤离；卸载中的单位会在重新加载时自清理。

> 范围说明：原版村庄没有"一个固定半径"，袭击以村庄中心（钟）为准。援军的防区/巡逻按 **袭击中心水平 24 格**计算，护送和流明为 96 格；触发要求玩家在袭击中心 64 格内、且附近有钟。

## 2.55 援军开门 / 爬梯 / 空坠斩触发（2.3.21）

- **开门**：援军的寻路允许开门/穿门，遇到关闭的木门会自动打开并 1 秒后关上；
- **爬梯**：站在梯子/藤蔓上会持续向上爬（0.2 格/tick）；
- **床的认领**：随从绑床现在像村民一样**占用该床的 HOME POI**，村民不会再认领这张床；纸绑床时如果床已被村民占用，会提示换一张；
- **空坠斩触发**：不再看"玩家是否攻击袭击者"，改为：玩家**副手举着流明灯**，且**视野内（约 60°）出现本场袭击者**时触发；距离按**水平 x/z 48 格**计算，**用望远镜观察时放宽到 128 格**（流明身边 8 格无袭击者、6 秒冷却仍然保留）。

## 2.7 援军血条（2.3.26）

- 援军进场后，96 格内的玩家会看到一条蓝色 Boss 血条「**流明援军**」；
- 进度 = **流明 + 14 名随从的总当前血量 / 进场时总最大血量**（死掉的单位按 0 计，所以掉血会直接反映）；
- 袭击结束/援军全部撤离后血条自动消失。

## 2.6 援军移速与空坠斩（2.3.16）

- **移速**：援军落地时统一 **0.30**（与原版基础一致，避免高速滑行/寻路打滑）；
- **空坠后的护送连携（2.7.4 重做）**：流明瞬移落点后两名护送分工——
  - **Unit 13 立刻出发**（在 Boss `teleportTo` 的**同一 tick**，不等 18 tick 后的落地斩击）：沿地面连续迅冲回 Boss 身边，
    沿途用**扫掠判定**斩击袭击者。参数：1.4 格/tick、**每 tick 都冲（20 Hz，对齐玩家迅冲斩的 quick 段 1 帧节奏）**、扫掠宽度 1.4 格、
    `frostDamage` 2 点、**整次返航每只敌人最多挨一次**、最长 160 tick、水平距 Boss ≤3 格归队；
    动画用 `mistletoe:escort_rush`（`rapid_slash` 去掉 Root 位移 + 裁到主段 0.633 秒、2.0x 速度循环），拖尾是沿段撒出的 `END_ROD`；
  - **Unit 12 仍在 Boss 落地后（18 tick）**对离流明最远的袭击者做空坠斩，与 Unit 13 的返航形成前后夹击；
  - 迅冲**不消费寻路路径**：每 tick 朝目标直线冲、段前做落差（±1 格）与碰撞预检，受阻就中断当前连冲、
    改用 `getNavigation()` 绕一段，下一 tick 继续冲（等价于绕开建筑，但不会因为高速跑路径而卡住）；
- **初雪**：援军流明落地即切「初雪」刀，近身就放初雪七连（orientation 先面向目标，避免扇形空刀）；
- **空坠斩**：玩家攻击袭击者时，只要流明 **8 格内没有袭击者**，她就会瞬移到玩家上方（约 8 格高）并下坠，约 0.9 秒后对目标发动斩击（带传送/暴击音效与横扫粒子）；同一流明 6 秒冷却。

## 3. 流明领队（需要 OP）

把**普通无主随从**绑定给一位流明·星：

```
/lumen_duty leader <随从> <流明·星>
```

- 随从会跟随这位流明（同维度且存活时），领队不可用时回到绑定位置；
- 不会占用玩家主人 UUID，也不能再被食物驯服；
- 村庄守卫不能同时当领队（二选一）。

## 4. 袭击波次记录（需要 OP）

```
/lumen_duty wave
```

- 记录最近一波的**实际落点**（mixin 注入 `Raid.spawnGroup`）；
- **只存在本次开服内存里**，重启清空；不修改原版刷怪。

## 5. 其它命令一览

| 命令 | 权限 | 作用 |
|---|---|---|
| `/lumen_duty follow <随从>` | 主人 | 恢复跟随 |
| `/lumen_duty guard <随从> <半径>` | 主人 | 进入选点模式，再右键方块 |
| `/lumen_duty status <随从>` | 主人 | 查看职责状态 |
| `/lumen_duty village <随从> <中心> <岗位>` | OP(2) | 登记村庄守卫 |
| `/lumen_duty village_bed <随从> <床>` | OP(2) | 分配村庄守卫的床 |
| `/lumen_duty leader <随从> <Boss>` | OP(2) | 绑定流明领队 |
| `/lumen_duty wave` | OP(2) | 查询本次袭击最近一波落点 |

## 6. 已知边界

- 暂无自定义指令 UI（先用物品/命令）；
- 提灯小屋、自动认领床、14 人自动出征与接防、流明战时专用 AI **未接入**（`DutyRules` 的 8+2+2+2 岗位规则已经写好并有单测，后续可接）；
- 村庄守卫的「本村」按登记时的中心/岗位记录，不会随每场袭击重新计算；
- 波次记录不持久化；
- 玩家随从死亡后的复活仍走原来的玩家重生点逻辑（已改为持久化，关档不丢）。
